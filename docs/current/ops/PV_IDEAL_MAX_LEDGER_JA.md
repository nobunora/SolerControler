# 予報非依存の理想最大発電量台帳

## 計算・更新

1時間の最大量は、日付・時刻・設備形状による快晴POA基準電力量 B と、全時間で共有する係数 C の積。太陽高度・季節はBで変化する。気温補正・天気予報・忘却・時間帯別係数は使わない。

実際のh:00とh:30のPV電力量を合計する。現在の最大量との差が **0.01 kWhを超えた場合だけ** Cを上げる。欠測を0にしない。低日射の追加閾値・分母floor・時間帯別fallbackは作らない。B=0で0.01 kWhを超過する場合は明示エラーで、台帳更新を中止する。

過去の発行値は更新後の最大量へ置き換えない。実績到着時刻と実発行時刻を分ける。事前値なし・時刻証拠不足・実績待ち・未来区間を成功として数えない。既知期間の再現は物理的絶対上限や未知期間の精度の証明ではない。

## 自動更新の経路

既存の予測専用Jobは、保存済み予測の回復、CSV取得、実績DB取込、従来の予測計算の順に実行する。DB取込成功後、新台帳を更新する。rawの重複取込が冪等終了しても新台帳処理へ到達する。settings-only回・raw失敗時は呼ばない。

新台帳は通常forecastの成功条件に追加しない。台帳の通信・整合性・保存失敗は `pv_ideal_max_import` の `severity=ERROR/status=failed/error_type` として記録し、完了済みの実績取込と後続forecastは継続する。例外messageや保存先識別子は出さない。台帳自身のCAS・checksum検査は維持し、その実行での再書込み・古いcopyへのfallback・自動初期化は行わない。次の通常実行では空directoryへ本番currentを新規checkoutしてから処理する。実績取込本体の失敗は従来どおり伝播する。

予測Jobの子は旧計画アーカイブを無効化しているため、新台帳のprefixを `PV_IDEAL_MAX_GCS_PREFIX` で明示的に引き継ぐ。この値は既存prefixから実行時に導出する。通常は追加の `.env` 設定は不要。直接実行の既定は従来の `night_plan_archive_prefix()`。旧計画保存namespaceは変更しない。

## 計画への適用と料金削減の契約

### 2026-11-12: 太陽位置ごとの能力補正

計画への適用は `physical_pv_ideal_max_local_v1` とする。保存済みの実績を利用可能時刻順に読み、
太陽高度10度・方位30度の区分ごとに係数を再構成する。実績がその区分の基準量×係数を0.01kWh超えた場合だけ、
同じ区分の係数を実績/基準量へ更新する。別区分へ伝播させず、未観測区分は係数1の基準量を使う。
天気・気温・忘却・近傍区分へのfallbackは使わない。欠測と実測0、完了区間、利用可能時刻の契約を維持する。

旧global-v1台帳・実績・過去発行値は保持し、cloudのcurrentを書き換えずに局所曲線を再構成する。
取得済みsnapshot内のSQLiteだけを最大26,304実績まで読む。新しい外部要求やdashboardのDB読取りは追加しない。
原本にはprojection policy、区分係数、採用した実績、当日各時間の区分、snapshot SHAを保存する。
旧global-v1の単一係数で過去予報を再計算した残差は新方式へ持ち込まない。局所方式の事前発行値と
取得時刻の揃った実績だけを既存のforward蓄電池・料金非悪化条件で評価し、未充足時は中立とする。
本番の残差履歴取得はlocal-v1導入日2026-11-12以後に限定する。対象日より前の同方式実績がなければ
snapshot履歴を取得しない。明示した保存snapshotによる隔離シミュレーションはこの導入日制約と区別する。

保存3,168観測・条件の揃った42日の比較で、未観測昼間区間は5/15区分で33、10/30区分で7となり、
両者の当日ピークは1.88840kWhだった。係数1から上方更新されていない区間はそれぞれ175と129であり、
観測があっても基準量を超えていない区分を含むため未観測とは区別する。時刻だけの区分は季節による太陽位置の違いを区別できないため採用しない。
従来方式に対して翌日上限超過は13から71時間へ増える。この比較は保存された利用可能時刻による履歴再生であり、42日間の本番事前発行の精度実証ではない。
これは将来実績を必ず覆う保証ではなく、朝の超過を別の太陽位置の能力証拠として扱わないための範囲制限である。

以下のMは、この局所曲線による時間別能力値を指す。旧global-v1の共通係数Cは保存台帳の履歴情報として保持する。

最大能力 M=B×C と当日の発電見込みは別の値とする。通常forecastは保存された予報日射を既存の時間区間契約で正規化し、快晴GHI基準Qに対する倍率 w=min(F_GHI/Q,1) を用いて発電見込み M×w を計算する。幾何学的夜間は0とする。天候補正は台帳のCや過去の発行値を変更しない。日中日射の欠損は既存の短い内部欠損補間契約に従い、それ以外はエラーとし、快晴や実測0を発明しない。

最上位の目的は電気料金削減とする。売買電量、買電ゼロ、満充電は候補選択の目的に追加しない。夜間充電費・日中買電費・売電収入・既存の残存電力評価を含む金額を比較し、同額時だけ低い実現可能SOCを選ぶ。誤差シナリオの発電量は各時間で min(発電見込み×シナリオ倍率,M) とし、通常分布や曇雨の上振れを能力値の超過として使わない。Mと発電見込み、予報の時刻・hashを保存し、同じ入力で再計算できるようにする。

充電目標だけで既存の蓄電量は減らせない。SOC候補は想定夜間放電後の残量以上とし、日中再生もその実現可能な開始量から行う。消費・発電・想定放電が0なら既存SOCを保持する。明示的なas_ofだけを渡した台帳再計算も通常計算と同じ選択経路を通し、未来の台帳状態を使わない。従来calibrationを明示する経路は従来モデルの再計算として区別する。

sourceは `physical_pv_ideal_max_local_v1` とし、`weather_adjustment_applied=true` で直接能力値を採用した過去原本と区別する。原本の `decision_rationale.pv_ideal_max` に設備fingerprint、取得/状態時刻、snapshot SHA、区分係数/revision、時間別能力値と天候補正後の発電見込みを記録する。公開時の鮮度検証に使うrootのretrieved_at/provider_issued_atは天気予報の原時刻を使い、台帳取得時刻はcapability_retrieved_atに分ける。forecastの読取りで台帳の発行値追加・係数更新・cloud publishを行わない。明示calibrationを渡す過去再計算は従来の計算を維持する。

台帳未初期化・読取り失敗時は従来予測へ戻り、失敗は構造化ERRORへ記録する。新しいgateやretryを追加しない。公開処理は同じ設備に限り新モデルと従来 `physical_clear_ghi_annual1` の切替を認め、未知モデル・設備変更の拒否と同一モデル内の時刻後退拒否は維持する。制御imageや機器設定を変更せず、以後の通常制御は公開された計画を従来契約で読む。

データ経路は台帳GCS→計算Job→計画原本/forecast_hourly→既存bootstrap/history→API→browser。HTTP handler・要求数・cache方針を変更しない。新sourceの時間別PVとSOCが同じ原本から生成されること、台帳失敗時の従来予測継続、既存の初期history要求0/遷移後1/再利用を検証する。

## 保存と復元

既存archive prefix内の別namespace `pv_ideal_max/<geometry fingerprint>/` を使う。旧 `clear_ghi` や計画原本を変更しない。

- 整合したSQLite backupをSHA256名のgzip snapshotとしてcreate-only保存。
- `current.json` を読んだ世代条件で更新し、競合時は終了。blind retryや古いcopyでの上書きはしない。
- 毎回空の一時directoryへ指定世代を復元し、snapshot SHA、model/geometry、C/revision、SQLite quick_checkを確認。
- pointerなしは `uninitialized`。自動初期化・暗黙リセットをしない。破損・snapshot欠落はエラー。
- cloud初期化実時刻を評価境界として保持し、区間開始と保存された発行時刻の両方がその境界以降の場合だけ運用評価する。研究用seedの過去時刻を本番成績に読み替えない。
- 共有deadline60秒、各SDK操作は最大4秒、SDK retryなし。圧縮snapshot bytesと更新結果を記録。

履歴増加に伴うsnapshot転送量は運用で測定する。通常状態は1行、明示的な時間別reportは31日以内の索引範囲だけを読む。HTTP/dashboard経路は追加しない。

## 正規ローカル入口

`scripts/run_pv_ideal_max_from_env.ps1` は既存の `production_env.ps1` から設定を読む。秘密や保存先識別子をコマンドへ書かない。

- `-Mode ValidateSeed -StateDirectory <local directory>`: seedのローカル検証。
- `-Mode InitializeCloud -StateDirectory <local directory>`: 明示承認後の初回保存。既存台帳は置換しない。
- `-Mode Report -FromDate YYYY-MM-DD -ThroughDate YYYY-MM-DD -AsOf <offset付き時刻> -OutputPath <新規JSON>`: 本番台帳からread-only復元して1時間別評価。

通常reportは部分集合を返す。全原本の復旧受入では、空directoryに復元したcurrent_state・observations・predictionsの全行と移行元を照合する。初期化の承認はJobデプロイ・merge・機器操作の承認と区別する。

訂正された同一実績は自動上書きせず、別の明示的な再構築を要求する。保存失敗後は正規経路で現在版を照合してから再開し、係数や原本を消してやり直さない。
