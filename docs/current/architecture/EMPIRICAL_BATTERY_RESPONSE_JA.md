# 実績に基づく蓄電池応答・時間別発電補正の契約

## 目的と適用範囲

最優先目的は電気料金の削減とする。SOC選択は既存の金額目的関数
「夜間買電費用 + 日中買電費用 − 売電収入 − 残存電力評価」で比較する。
買電0・売電0・ピークSOC95%を上位の選択条件にしない。残存電力評価は現金収支と分けて記録する。

本変更は予測・計算・監査の変更であり、この文書の作成やローカル試験の成功は本番適用を意味しない。
本番適用には既存の承認・正規ゲート・正規ラッパーを使う。03時制御、23/07時の所有権、
停止時刻、設定保持に関する歴史的障害保護契約は変更しない。

## 充放電とSOCの共通換算

AC側の充電量をC kWh、放電量をD kWh、区間長をΔt時間とする。
aは充電AC 1 kWh当たりのSOC増加ポイント、bは放電AC 1 kWh当たりのSOC減少ポイント、
dは待機中のSOC減少ポイント/時間である。

    SOC次 = clip(SOC現在 + a(T,h)×C − b(T,h)×D − d×Δt, 0, 100)
    a(T,h) = a0 + aT×(T−T基準) + u[h]
    b(T,h) = b0 + bT×(T−T基準) + v[h]
    有効条件: 全使用温度・時間で有限、0 < a(T,h) ≤ b(T,h)、d ≥ 0

夜間充電・昼間シミュレーション・残存電力換算・表示計画は同じ応答係数を使用する。
単一の対称効率を追加で掛け、実績係数に既に含まれる損失を二重に適用してはならない。
内部容量相当値とAC側の供給可能量は区別する。推定容量相当値を実測内部容量と表示しない。

SOCと充放電実績の区間契約は、既存計算と同じ
「現在行のAC電力量が、直前の連続30分行から現在行までのSOC変化を説明する」とする。
発電・負荷の時間別集約は既存のタイムスタンプ時ラベルを維持する。
誤差が減ることを理由に時刻をずらさない。h:00の実測SOCは生の読取り値として保持し、
根拠なく「h時区間開始SOC」と言い換えない。

## 実績学習と温度の出所

前日までの最大90日を対象とする。学習区間の両端SOCは5〜95%、間隔は連続30分、
電力量とSOCは有限の有効値に限定する。未来データを学習へ混ぜない。
時系列を前80%の学習と後20%の検証に分け、学習に15日以上、
充電・放電それぞれ100区間以上を要求する。

温度係数を学習するには、温度の出所を次の順で区別する。

| 出所 | 意味と扱い |
| --- | --- |
| measured_battery | 実測蓄電池温度に条件付けた応答 |
| observed_outdoor | 実測外気温に条件付けた代理モデル。蓄電池の物理温度係数とは呼ばない |
| forecast_outdoor | 将来計算用の予報気温。実測温度として学習しない |
| battery_temperature_estimate | 出所が明示された将来蓄電池温度推定。外気温と区別 |
| 欠損・出所不明 | 新規温度係数を採用せず、共通応答または直前採用モデルを使う |

温度学習には同じ出所で充電・放電それぞれ100区間以上、15日以上、P90−P10 ≥ 8℃を要求する。
時刻別平均からの温度偏差の標準偏差が1℃未満なら、温度と時刻の分離が弱いため学習しない。
学習範囲外へ外挿せず、温度を学習時の最小〜最大に制限する。
実測蓄電池温度モデルへ外気予報を無条件代入しない。

正則化付き一次推定は有限の線形解法で計算し、物理条件を満たさない解を不採用とする。
負の待機損失が出る場合は待機損失0の制約面でもう一度解く。
反復上限は200回だが、現行解法は最大2回で終了する。未収束や不正値で制御を停止せず、
直前採用モデル、または有効な共通係数へ戻す。

外気温の日平均を使用する場合は、将来も予報日平均を入力する。日平均で学習した係数へ
瞬時の時間別気温を投入しない。新規の気象実績には取得日時と出所・日平均区分を保存する。
旧キャッシュに取得証拠がなければ遡って作らず、温度学習から除外する。

## 蓄電池の時間帯差

時間別の充電・放電調整u[h], v[h]は、温度を含む共通モデルの残差から求める。
一方向の有効区間が20未満の時間は調整0とし、それ以上はn/(n+20)で縮小する。
温度と時間の説明できる差を先に取り除き、同じ差を二重加算しない。
運転モードや出力の違いで説明できない時間帯差を物理的な温度特性と断定しない。

## 発電予測の時間・天気別残差

発電能力台帳は独立のまま保持する。補正対象は予測値である。

    残差[d,h,w] = 実績PV[d,h] − 保存原本の未補正予測PV[d,h]
    n[h,w] = 有効な異なる過去日数
    δ[h,w] = 0                                      (n < 20)
    δ[h,w] = n/(n+20) × mean(残差[d,h,w])            (n ≥ 20)
    補正PV[h] = clip(未補正予測PV[h] + δ[h,w], 0, 保存された最大能力[h])

対象期間は最大90日、同じ日・時・天気区分から1標本だけを採る。
現在日・未来日・不完全な区間・非有限値・負の実績は除外する。
保存原本は同じrunの24時間を要求し、予報発行が対象日の07時以前、
発行時刻の出所がplan、記録時刻が当該予測のas_of以前であることを確認する。
後から再構築した予測や書換え可能な最新値を、当時の保存原本として使わない。

実績の計測時刻と入手時刻は別である。入手時刻はavailable_at、ingested_at、updated_atの
明示された記録から判定し、計測時刻+30分やファイルmtimeで捏造しない。
記録不足の場合は学習へ入れず、除外日数・不足理由を出力する。

保存スナップショットの既存JSONへ、時別の未補正PV、最大能力、天気区分、モデルID、
能力台帳revisionを追加する。過去の予測値は変更しない。既存スキーマを変更しない。
07時のスナップショットには、その予測原本の蓄電池応答も保存する。後日の発電補正検証は
この凍結済み応答を使い、未来に再学習した応答へ置換しない。応答が未保存の旧原本は除外する。
半時間別の予測がない場合、時間予測を各半時間へ1/2ずつ配分する近似を明示して検証する。
読取りは対象期間を限定し、最大90×24×8行+超過検出1行に制限する。
上限超過・取得失敗は不完全な切り詰めデータを採用せず、中立とする。
実績入手時刻が全く不足する場合は余分なスナップショット読取りも行わない。

## 採用判定

蓄電池候補は後続の独立検証区間で、SOC誤差が厳密に改善し、
買電量MAEと同じ料金契約による金額評価MAEが悪化しない場合だけ採用する。
比較用の共通係数も学習期間だけで求める。検証期間を含む運用係数を候補の事前値に使わない。
さらに現在の運用係数との比較でもSOC・買電量・金額の予測誤差が悪化しないことを要求する。

発電補正は各検証日の発行時刻以前に入手済みの過去実績だけで係数を作り、後続日に適用する。
20日以上の同一bin履歴がある後続検証日を5日以上必要とする。
採用条件はSOC MAEが1e-9より大きく改善し、買電量MAEと金額MAEの増加が1e-9以下であること。
無効な検証foldがある場合、または評価器がない場合は新規採用しない。
直前の有効な採用モデルがあれば保持し、なければδ=0とする。

金額は同じ料金契約を固定したモデル評価であり、確定請求額や実証された節約額とは別である。
採用・不採用、学習日、入力SHA、温度出所、検証誤差、対象外理由を予測原本に残す。
原本の再現性と最大能力台帳の独立性を維持する。

## 監査と日次照合

設定変更不要でも必須の要求・観測モードを保存し、空の項目集合で成功としない。
成功条件は「必須項目が存在し、要求値と観測値が一致」である。
再書込みで不足ログを補おうとしない。

日次比較は予測と実績で一致する完全取得区間だけに限定する。未取得値はNULLとする。
瞬時SOCと区間ラベルを区別し、時刻契約が確定しない比較はINCONCLUSIVEとする。
料金削減を評価する際は、実績の取得範囲・評価料金・残存電力評価の有無を併記する。
