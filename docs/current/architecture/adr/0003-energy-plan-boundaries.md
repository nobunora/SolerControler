# ADR 0003: 予測・計画・実機設定を分離する

## 決定

予測は `forecasting/`、SOCと充電量の計画は `energy_plan/`、KP-NETへ送る設定プロファイルは `kpnet/`、時刻別の実行は `runtime/` が所有する。

## 背景

予測値、経済最適化、機器の候補値・時刻制約は異なる理由で変更される。一つのモジュールに置くと、予測改善が機器設定や安全条件を壊しやすい。

## 結果

- `night_charge_plan.json` を計画と実機設定の受け渡し境界とする。
- KP-NET候補値への丸めや同日内時刻制約は `kpnet/` に残す。
- 計画側は外部サービスのHTTP・画面・DB詳細を直接扱わない。
