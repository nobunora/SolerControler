# 計算・制御・表示の分離と移行契約

利用者承認: 2026-10-07。移行前の固定基準はPR #57のmerge commit `fd022e7`。既存の計算、KP-NET通信、SOC監視、表示を流用し、役割別の入口・依存・保存計画の受渡しを追加する。

## 構成

計算用imageは既存のforecast jobを実行し、同じ予想・計画を保存する。制御用imageはその計画の原本を読み、既存のmode-only操作・SOC監視を使う。表示用imageは既存dashboardを使う。検査は制御候補と同じimageで別の入口から実行する。

画面の経路はbrowser→HTML/既存bootstrap API→GCS事前集計である。そのwriterは計算完了後、既存`archive_plan_snapshot`で不変原本と`night_charge_plans`の当日/latestを更新し、制御用採用版の公開後に同じ原本から事前集計を更新する。03の生成を移す際、このlatest更新を落としてはならない。画面endpoint・初期request数・履歴の遅延読取・cache契約は変えない。

制御用に科学計算・描画・Drive・PostgreSQL SDKを含めない。計算用と表示用の依存は、既存の使用経路と起動検証を根拠に選ぶ。依存の版は取得済みimageから確認し、制約ファイルで固定する。既存のmathematical model変更をこの構成移行へ混ぜない。欠損実績の残差処理は既知の別問題であり、同一入力の比較と独立して扱う。

## 保護する契約

- HISTORICAL_FAILURE_LOCKの根拠: 2026-08-29のcross-slot ownership置換、2026-09-06の遅延CSV/SOC取得失敗、2026-09-18/22の07時グリーン復帰。
- 23時standbyと07時greenは計画・DB・03の成否に依存しない。
- 03時SOCは直接読取だけを使う。実績CSVを現在SOCの代用にしない。
- 03時06:45監視停止、06:50最終standby開始期限、06:55 I/O停止を維持する。
- forced/greenは動作モードだけを変更する。目標SOCは監視で判定する。
- SOC監視と設定読み戻しは既存実装を流用し、操作結果が不明な書込みを自動再送しない。
- 計算と表示の原本選択・履歴復旧・当時の生成時刻を維持する。表示GETから計算や履歴アーカイブ読取を開始しない。

03時の計画生成・CSV取得を計算側へ移すことは承認された契約変更である。充電速度の推定も計算側で行い、その値を既存監視へ渡す。旧入口は移行検証と復帰のため保持し、既存テストの既定動作は変えない。

## 受渡し

計画は原本JSONバイト、SHA-256、対象日、充電速度推定を保存する。計算済みの数値を制御側で再計算しない。内容で識別する不変版と当日採用版を同時に公開する。03時は採用版の対象日・型・有限値・ハッシュを検証してから原本をローカルへ復元し、監視に渡す。取得・検証失敗時は旧日計画へfallbackせず、既存のstandby安全処理を試みて失敗として記録する。07時は独立して実行する。

## 受入・削除条件

1. 同一保存入力の予想・計画の数値と原本が保持される。
2. 保存済み実計画を旧監視と新入口に渡し、SOC到達・取得失敗・時刻境界の操作トレースを比較する。
3. 必須品質ゲート・保護テスト・役割別の依存だけでの起動検証を通す。
4. Cloud Buildを成功確認し、候補でCSV/計画の経路と実機mode-only往復・60秒保持・正確な復元を確認する。
5. 新構成の全現役image原本と設定・ソース・秘密値を保存し、稼働と表示を確認する。
6. 削除直前に全Job/Serviceの参照を再取得し、現役・検査・復帰版を除外する。削除対象のOCI原本を検証してから削除する。

途中状態、模擬テストだけの成功、画像の参照先一致だけで旧imageを削除しない。新規のクラウド操作は既存の.env読取・gcloudラッパー・段階状態に統合し、設定値をコマンドや公開ログへ出さない。
